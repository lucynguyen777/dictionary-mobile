# v1.2.3 Production Gate Smoke

## Goal

Prepare the next implementation work after v1.2.2 by separating:

- features already implemented but production-gated by env/provider smoke;
- accepted/staged features that can be built next;
- still-blocked source/license/native/provider work that must stay visibly unavailable.

The recommended product choice is **Profile/Settings opt-in beta sync** with a manual **Sync now** action. Do not add automatic foreground, background, or realtime sync in this module.

## Current Implemented But Production-Gated Features

| Feature | Code state | Gate before user-visible production claim |
| --- | --- | --- |
| Supabase Auth | Implemented with env-based config and Profile auth UI | Supabase project env, redirect allow-list, web/native smoke, sign-out no-local-delete smoke |
| Manual beta Cloud Sync | Implemented runner/local ports/lifecycle/manual action | Auth smoke, RLS probes, two-user/two-device smoke, rollback plan |
| DeepL translation | Implemented through Vercel `/backend-proxy` | Vercel server env vars, authenticated smoke, quota/provider-unconfigured smoke |

- Uyghur monolingual baseline beyond the current insufficient candidate set;

## Smoke Checklist

### 1. Supabase Auth

Repo env names:

```bash
EXPO_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
```

User setup:

1. In Supabase Dashboard, enable Email/Password auth.
2. Add redirect URLs:
   - `https://dictionaire-mobile.vercel.app/auth/callback`
   - `dictionairemobile://auth/callback`
   - any local Expo web URL used for manual smoke, for example `http://localhost:8081/auth/callback`.
3. Use only the publishable key in Expo/web env. Never expose a service-role key.
4. Create two disposable test users for sync smoke.

Official docs:

- Supabase redirect URLs: https://supabase.com/docs/guides/auth/redirect-urls
- Supabase React Native auth quickstart: https://supabase.com/docs/guides/auth/quickstarts/react-native

Smoke:

- Profile shows unconfigured state without env.
- Profile can sign in with a valid test user with env.
- Bad password shows a provider error and does not delete local data.
- Sign out clears Supabase session and keeps local data.

### 2. Vercel Backend Proxy Providers

Required server-only Vercel env vars:

```bash
DEEPL_API_BASE_URL=https://api-free.deepl.com
DEEPL_API_KEY=YOUR_DEEPL_KEY
OPENAI_API_KEY=YOUR_OPENAI_KEY
OPENAI_TEXT_MODEL=YOUR_MODEL
```

Optional quota env vars:

```bash
PROXY_DAILY_AI_REQUEST_LIMIT_PER_USER=25
PROXY_DAILY_TRANSLATION_CHARACTER_LIMIT_PER_USER=20000
PROXY_MONTHLY_CHARACTER_LIMIT_PER_USER=200000
PROXY_MAX_TEXT_INPUT_CHARS=5000
PROXY_MAX_GLOSSARY_ENTRIES=1000
PROXY_LOG_RETENTION_DAYS=30
```

User setup:

1. Add the vars in Vercel Project Settings -> Environment Variables.
2. Mark provider keys sensitive if the dashboard supports it.
3. Redeploy production after env changes.

Official docs:

- Vercel environment variables: https://vercel.com/docs/environment-variables

Smoke:

```bash
curl -I -L --max-time 20 https://dictionaire-mobile.vercel.app
curl -i -X POST --max-time 20 https://dictionaire-mobile.vercel.app/backend-proxy/proxy/translate/text
```

Expected unauthenticated proxy result is `401 unauthorized`. A signed-in smoke with a Supabase token should then reach provider validation/provider response instead of static HTML.

### 3. Manual Beta Cloud Sync

Recommended product behavior:

- Profile/Settings opt-in beta toggle.
- Whole MVP domain set; no per-domain picker in first production path.
- Manual **Sync now** only.
- No automatic app-start, foreground, background, or realtime sync.
- Sign-out never deletes local data.

Smoke:

1. Sign in as User A on browser/device 1.
2. Enable beta sync and tap **Sync now**.
3. Create/update/delete one folder and one saved word locally.
4. Tap **Sync now**.
5. Sign in as User A on browser/device 2.
6. Tap **Sync now** and verify create/update/tombstone behavior.
7. Sign in as User B and verify User A data is not visible.
8. Sign out and verify local data is preserved.

### 4. Feedback Submission

Recommended MVP:

- Supabase `feedback` table for durable storage.
- Resend backend email notification to a support inbox.
- RLS own-row insert/select as appropriate.
- Spam throttle and failure state before production claim.

User setup:

1. Choose support inbox, for example `support@your-domain.com`.
2. Create/verify a sender domain in Resend.
3. Add a server-only `RESEND_API_KEY` in Vercel.
4. Decide retention copy, for example "Feedback is retained for support and product improvement until manually deleted or account deletion is requested."

Official docs:

- Resend send email API: https://resend.com/docs/api-reference/emails/send-email

### 5. Google Sheets Export

Recommended MVP:

- Backend-mediated Google OAuth.
- Least privilege first: prefer `drive.file`, add `spreadsheets` only if the route needs it.
- Store refresh tokens server-side only and encrypted/tokenized.
- Keep CSV/XLS/Anki fallback active.

User setup:

1. In Google Cloud Console, create/select a project.
2. Enable Google Sheets API and Google Drive API.
3. Configure OAuth consent screen.
4. Create an OAuth Client ID for a web app.
5. Add authorized redirect URI:

```text
https://dictionaire-mobile.vercel.app/backend-proxy/oauth/google/callback
```

6. Add server-only Vercel env vars after the backend route exists:

```bash
GOOGLE_OAUTH_CLIENT_ID=...
GOOGLE_OAUTH_CLIENT_SECRET=...
GOOGLE_OAUTH_REDIRECT_URI=https://dictionaire-mobile.vercel.app/backend-proxy/oauth/google/callback
```

Official docs:

- Google OAuth client help: https://support.google.com/cloud/answer/6158849

### 6. Native OCR/STT Dev-Client

Recommended MVP:

- OCR first candidate: `@infinitered/react-native-mlkit-text-recognition`.
- STT first candidate: `expo-speech-recognition`.
- Keep native packages behind adapter contracts.
- Keep Expo Go/web fallback honest and unavailable when native runtime is missing.

User setup:

```bash
npm install -g eas-cli
eas login
eas build:configure
eas build --profile development --platform ios
eas build --profile development --platform android
```

Official docs:

- Expo EAS build setup: https://docs.expo.dev/build/setup
- Expo EAS build profiles: https://docs.expo.dev/build/eas-json

Smoke:

- Native OCR: pick/capture an image with clear English/Vietnamese text -> OCR lines appear -> selecting a line triggers lookup.
- Native STT: speak a short phrase -> transcript appears -> lookup works.
- Airplane/offline behavior is documented instead of assumed.
